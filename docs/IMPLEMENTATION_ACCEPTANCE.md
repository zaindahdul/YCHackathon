## Verification required before “done”

1. **Context receipt:** in the execution task, report the main commit and product branch inspected, name both respondents’ distinct priorities, and state which requirement IDs are being implemented. Proceed with work; do not stop at acknowledgment or another plan.
2. **Automated behavior:** run `npm ci`, `npm test`, `npm run typecheck`, `npm run build` in the actual `project-2/` workspace under Node24. If integrated into main, also run main’s `npm run check`, `npm run build`, `npm run format:check` and document checks. Main’s 154 old tests alone do not test Launchpad. Use the lockfile; inspect dependency advisories and repair relevant issues with compatible checks.
3. **New behavior checks:** add meaningful tests for implemented requirements and real failure modes: malformed input/media, unauthorized private kit/report, retries/concurrent workers, stale leases, partial writes, outbound approval/caps, narrative leakage, activation attribution and any reply workflow. Tests that simply inject finished kit fixtures are not an agent workflow test.
4. **Browser journeys:** independently exercise intake → writing state → actual generated kit → review/edit → explicit launch/share → results/report. Exercise comment review and media processing if shipped. Include fresh session/private-link isolation, back/reload, invalid/missing inputs and failure/retry. Record screenshots at desktop and mobile, inspect them, and repair confusing copy/controls. Do not expose tokens or private content in public evidence.
5. **Agent/integration proof:** where credentials and authorization exist, demonstrate the actual bounded provider task and persisted outcome; otherwise report that boundary and test the adapter locally. Do not enable outreach, spend, deployment or account changes merely because this checklist mentions them. Avoid sends/spend in automated tests.
6. **Independent review and repair:** a reviewer outside the implementation pass checks the complete journey and material security/data/UX gaps. Fix findings and rerun affected checks. A screenshot or passing suite does not overrule a broken interaction or absent feature.
7. **Delivery evidence:** report commit, branch/PR, matrix status per requirement, exact commands/results, rendered artifacts, unresolved concrete blockers and manual interventions. Verify any authorized deployment at its actual URL; local success is not a deployment. Keep the tree clean and preserve other branches/history.
